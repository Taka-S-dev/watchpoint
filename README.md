# watchpoint

見張っているファイルやページのコピーを取ってきて、テキストに直し、確認済みにしたときから何が変わったかを出す。

- 元のファイルは読むだけ。開いたり書いたりしない（手元にコピーしてから処理する）。コピーしている間も、持ち主は保存・名前の変更・削除ができる（ほかからの書き込み・名前の変更・削除を許して読む）
- 見張りごとに「読むポイント」を書いておき、変更と一緒に出す。AI エージェントに `check -f md -C` の結果を読ませれば、ポイントに沿って要約させられる
- 変更は `ack` で確認済みにするまで出し続ける（一度見ただけでは消えない）

Windows で動く（タスク スケジューラ・資格情報マネージャー・Excel / Word を使う）。

## 使い方の例

共有フォルダの質問表のうち、自分が回答者の行に質問が増えたり回答が書き換わったりしたら知りたい、という場合。

**最初に一度だけ（画面で）**

1. `watchpoint gui` を開き、「最初の見張りを追加」を押す（設定ファイルがなければ作る）
2. 質問表の場所を入れる（「ファイル…」で選ぶか、エクスプローラーの「パスのコピー」を貼る）。中身の表が出るので、見出しの行・行を見分ける列（No.）・見る列をクリックで選ぶ。`vars` の `me` に自分の名前を書いておけば、「回答者」列に自分の名前を見つけて「自分の行だけを見張りますか？」と聞いてくる
3. 読むポイント（「回答が変わったら要注意」など）を書き、「試しに取り出す」で比べる中身と知らせの例を見てから、「見張りを始める」を押す。保存して、いまの状態を基準にする
4. `watchpoint schedule install` で、5 分おきに自動でチェックするようにする（画面を開いている間だけなら「開いている間、自動でチェック」）

**手で書くなら**: `watchpoint init` で設定ファイルを作り、見張りを書く（Excel なら `key: No.` で行を突き合わせ、`where: {回答者: '${me}'}`（{ } の中の ${…} は引用符で囲む） で自分の行だけにする）。`watchpoint preview 質問表` でテキストにした結果を確かめ、`watchpoint doctor --fetch` で場所・資格情報・通知先を確かめる。

**ふだん**

```
タスク スケジューラ（5 分おき）: 間隔の過ぎた見張りをチェックし、新しい変更があれば drop_folder に知らせを置く
        ↓
通知アプリが知らせを出す「質問表（〇〇案件）: …」
        ↓
変更を見る
  ・watchpoint gui で差分を見る
  ・または「AI 用にコピー」（check -f md -C と同じ形）を Copilot などに貼り、読むポイントに沿って要約させる
        ↓
対応する（返信する、タスクにする など）
        ↓
確認済みにする: watchpoint ack 質問表 -m "No.15 は明日回答"
  → ここが新しい基準になり、次からはここからの変更だけが出る
```

- 知らせを見逃しても、確認済みにするまで変更は `status` と画面に残る
- 見ている間に自動チェックが新しい変更を取ってきても、`ack --seen <番号>`（画面の「確認済みに」も同じ）なら、見ていない変更までは確認済みにしない
- 閲覧数など、`report` や `match` に当たらない変化は自動で確認済みになり、たまらない

ほかの使い方:

- **朝にまとめて見る**: `watchpoint check -f md -C` の結果を AI エージェントに読ませて、前の日からの変更を要約させる
- **画面を開いたまま作業する**: `watchpoint gui` を開いている間は、各見張りをそれぞれの間隔（既定 30 分）でチェックし、Windows の通知で知らせる（打ち合わせの前後で資料がよく変わるとき）

注意: 自動の確認はサインインしている間だけ動く（PC を閉じていた間の変更は、次に動いたときにまとめて出る）。`drop_folder` に置いた知らせは、それを読んで表示するアプリが別に要る。

## 見張れるもの

| 種類 | source の例 | 比べ方 |
|---|---|---|
| Excel（.xlsx / .xlsm） | `\\server\share\質問表.xlsx` | `key` を付けると、その列で行を突き合わせて「追加 / 変更（項目ごと）/ 削除」と「列の追加・削除」を出す。付けなければ行番号付きのテキストで比べる。どちらでも、一度も計算されていない式は `=A1*2（未計算）`、取り消し線は `~~文字~~` と出し、コメント・図形とテキストボックスの文字・印刷のヘッダーとフッター・非表示のシートの印も比べる |
| CSV（.csv / .tsv） | `C:\export\issues.csv` | `key` / `columns` / `where` を付けると Excel と同じ。付けなければテキスト |
| Microsoft Project の計画（.mpp / .mpt、Project の XML） | `\\server\share\計画.mpp` | タスクを UID で見分けて「追加 / 変更（項目ごと）/ 削除」を出す（`key` を書かなくてよい）。比べるのは、名前・親のまとめ・開始・終了・期間・進捗・先行タスク・担当・基準計画・期限・メモ・ユーザー設定の項目と、計画全体の状況報告日と進捗。上に行を足してもずれる番号（ID・アウトライン番号）は比べない。`.mpp` を読むには、この PC に Microsoft Project が要る（手元のコピーを、マクロを止めて読み取り専用で開かせる）。Project がなければ、前と同じく変わったかどうかだけを見る |
| Word（.docx） | `\\server\share\仕様書.docx` | 見出し（自動の番号付き）・本文・表の行に加えて、ヘッダー・フッター・脚注・テキストボックス・コンテンツコントロールの中身もテキストにして比べる。変更履歴は `{++追加++}` `{--削除--}`、取り消し線は `~~文字~~`、コメントは `{>>名前: 文字<<}` と印を付ける |
| テキスト（.md / .txt / .json など） | `C:\notes\spec.md` | そのまま比べる（UTF-8 か Shift_JIS）。差分のまとまりごとに、その下の見出しを付ける |
| フォルダ | `\\server\share\議事録\*.docx` | ファイルの一覧（サイズ・更新日時）で、増えた・消えた・更新されたを出す。中身はコピーしない |
| Web ページ | `https://example.com/news` | 本文をテキストにして比べる。`selector` で見る部分を、`remove` で毎回変わる部分（閲覧数など）を指定できる |
| JSON の API（Redmine など） | `https://redmine.example.com/issues.json?...` | `records` の一覧を、`key` で突き合わせる。`paginate: offset` で全ページを取る |
| Confluence | ページの URL（`viewpage.action?pageId=…`、`/display/スペース/タイトル`、Cloud の `/pages/123/…`） | Server / Data Center は、人が見るページをそのまま読み、本文（`#main-content`）と、ページに出ている版・最終更新者・更新日の 1 行（`版: 4（田中、11月 20, 2026）`）を比べる。文字が変わらない改訂（書式・画像・マクロの設定）も改訂として出て、誰の改訂かも差分に出る。版が同じまま本文だけ変わったときは、マクロ（Jira の一覧、他ページの取り込みなど）が自動で変わったもの。添付ファイルの一覧（ページの「添付ファイル」の画面）も読み、`添付: 質問表.xlsx（版 3、2026-11-20 10:00）` の行で比べる。添付の差し替えはページの版を上げないので、これで気づく。`attachments: ['*.xlsx']` を書くと、ページの本文は見ずに、名前が当てはまる添付だけをダウンロードして中身で比べる（`key` で行ごと、`cells` で決まったセルも。ファイルごとに分けて比べ、あとから増えた添付も入る）。添付の一覧の版が前回と同じならダウンロードしない。REST API は呼ばない（切られている・使ってはいけないサーバーが多いため）。ログインの画面が返ったら比べずに知らせる。Cloud はページを画面側で組み立てるので REST API で読み、版番号だけを先に見て、変わったときだけ本文を取る。ページに埋め込んで表示している添付（Excel・Word の表示マクロ）は、中身がページの文字に入らないので、画面の見張りに「中身を見張る見張りを足す」が出る（押すと、同じページの `attachments:` の見張りを足す） |
| Web 上のファイル（Confluence の添付など） | `https://wiki.example.com/download/attachments/123/質問表.xlsx` | URL が Excel・Word・CSV・PDF・Project の計画などを指していれば、ダウンロードして、共有フォルダの同じファイルと同じように比べる（`key` で行ごと、`cells` で決まったセルも）。Confluence の添付のリンクに付いた版の指定（`?version=3` など）は外して、いつも最新を取る。ファイルの代わりに Web ページ（ログインの画面など）が返ったら比べずに知らせる |
| SharePoint の Office ファイル | `https://x.sharepoint.com/.../質問表.xlsx` | Excel / Word に読み取り専用で開かせ、手元にコピーを保存させる（同期もアプリ登録も要らない。Office のサインインを使う）。書くのはファイルの URL（Excel で［ファイル］→［情報］→［パスのコピー］）。「リンクをコピー」の共有リンク（`/:x:/r/…`）や、ブラウザで開いたときのアドレス（`/_layouts/15/Doc.aspx?…`）は設定の誤りとし、ファイルの URL が読み取れればそれを示す（「見張りを追加」では置き換えのボタンが出る）。`?web=1` などブラウザ用の指定は外して開く。開けなかったときは、Excel の言葉から「見つからない」「権限がない」「つながらない」「サインインの画面で止まった」を見分け、次にやることを添える |
| コマンドの出力 | `command: [git, -C, 'D:\repo', log, ...]`（source の代わり） | この PC で動かしたプログラムの出力を比べる。バージョン管理のコミット履歴、ほかのツールの一覧など、ファイルや API では取れないもの（下の「コマンドの出力を見張る」） |
| そのほか | | 中身が変わったかどうかだけ（ハッシュ） |

`fetch` を書かなければ source から種類を決める（`watchpoint list` で確かめられる）。

### コマンドの出力を見張る

`command` に、プログラムと引数をリストで書く。出力を `format`（`text` / `json` / `csv` / `tsv` / `xml`）として読み、`key` を付ければ 1 件ずつ突き合わせる。

```yaml
- name: docs のコミット                  # 特定のディレクトリへのコミットが増えたら知らせる
  command: [git, -C, 'D:\repo', log, -n, '30', '--date=iso', '--pretty=format:%h%x09%an%x09%ad%x09%s', --, docs/]
  format: tsv
  fields: [hash, author, date, message]  # 見出しの行が無い出力の列名
  key: hash

- name: 設計書のコミット                  # XML で一覧を出すツール
  command: [tool, log, --xml, -l, '20', 'https://repo.example.com/trunk/設計書']
  format: xml
  records: logentry                      # 1 件ごとにくり返す要素の名前。属性と子要素が項目になる
  key: revision
  columns: [author, date, msg]
```

新しいコミットは `追加 [hash=…] author=… | message=…` のように出る。

設定ファイルにコマンドを書けると、その設定ファイルを書き換えられる人が、あなたの権限でプログラムを動かせてしまう。そのため次のようにしている。

- **読むだけのコマンドしか書けない**: 書けるのは、読むだけと分かっている形だけ。バージョン管理ツール（git など）の履歴を読むサブコマンド（`log`・`show`・`ls-tree` など）と、`findstr`。git の作業ファイルを読むもの（`status`・`diff`・`blame`・`grep`・`ls-files`、`describe --dirty`）は書けない（作業ファイルは、リポジトリ自身の設定が名指す変換フィルターを通して読まれ、それはコマンドラインからは止められないため）。読むサブコマンドでも、ファイルに書き込んだり別のプログラムを動かしたりできるオプション（git の `-c`・`--output`・`--ext-diff` など）は使えない。シェルやスクリプトの実行環境（`cmd`・`powershell`・`python` など）、`docker exec` のように中で何でも動かせるもの、パスで書いたプログラム（`C:\tools\git.exe`。同じ名前の別物に差し替えられるため）も書けない。危険なものを数え上げて止めるのではなく、読むだけと分かっているものだけを通すので、知らない形はすべて止まる。書けない形を書くと設定の誤りになり、画面からも保存できない
- **リポジトリ側の仕掛けも止める**: git は、リポジトリの設定や `.gitattributes` で指定された外部のプログラム（変換フィルター・比較プログラム・署名を確かめるプログラム・fsmonitor・ページャー）を一切使わないように指定して動かす。この指定には git 2.40 以降が要る（古い git では、守れないまま動かすのではなく、エラーで止まる）。足りないデータを取りに行くこと（ssh・資格情報のプログラムが動く）も止め、それでも名指しできないプログラム（リモートの upload-pack など）がリポジトリ自身の設定にあれば、そもそも動かさずに取得失敗にする（共有フォルダにある作業コピーは、ほかの人も書き換えられるため）。自分の全体の設定は対象外。プログラムは PATH の中だけから探し、いまいるフォルダからは探さない
- **どうしても必要なときだけの抜け道**: 上に当てはまらないコマンド（たとえば `docker exec` で別の環境のツールを動かす）は、ターミナルで `watchpoint allow <name> --unsafe` を実行し、警告を読んで見張りの名前を入力したときだけ動く。画面からはできず、設定ファイルを書き換えるだけでは使えない。許可したものは「許可したコマンド」の一覧に赤い印で出る
- **許可したコマンドだけを動かす**: 初めてのコマンドは動かさず、「まだ許可していないコマンド」として取得失敗にする。中身を確かめてから、画面の「このコマンドを許可する」か `watchpoint allow <name>` で許可する。コマンドを 1 文字でも変えると、もう一度許可が要る（許可は Windows のユーザーごとに `%LOCALAPPDATA%\watchpoint` に残る）
- **書ける場所を限る**: `include` で取り込んだファイルと、共有フォルダ（`\\server\...` やネットワーク ドライブ）にある設定ファイルには書けない
- **つなげられない**: シェルを通さずに直接起動するので、`;` や `|` で別のコマンドをつなげられない。空の作業フォルダで動かし、入力は渡さない
- **止める**: `timeout`（既定 30 秒）で止め、出力は 20 MB まで。終了コードが 0 でなければ、エラーの出力を添えて取得失敗にする
- **見直せる**: 許可したコマンドは、画面の「設定」の下の「許可したコマンド」か `watchpoint allow`（name なし）で一覧できる。どの見張りが使っているかも出し、使っていない許可は印を付けてまとめて取り消せる。1 件ずつなら、画面の「取り消す」か `watchpoint allow <name> --revoke`
- 画面の「見張りを追加」からは作れない（設定ファイルに書く）。出力は UTF-8 で読み、読めなければ Windows の既定の文字コード（Shift_JIS）で読む

### 見張り方を選ぶ

上の表は「中身の変化」を見る場合。ほかに次の 2 つを選べる（画面の「見張りを追加」でも選べる）。

| 見張り方 | 書き方 | 使うとき |
|---|---|---|
| 中身の変化（既定） | 何も書かない | 何が変わったかを知りたいとき。`points`（読むポイント）と `notify_when`（知らせる条件）を書いておけば、`check -f md` や「AI 用にコピー」で、AI がそれに沿って要約し、知らせるべき変化かどうかを判断する |
| 決まったセルだけ（Excel） | `cells: [集計!F20, B3:D5]`、名前を付けるなら `cells: {合計: 集計!F20}` | 合計・状態・承認欄など、決まったセルの値だけが大事なとき。変化は `変更 [セル=F20] 合計: 100 → 120` のように出る。範囲は合わせて 2000 セルまで。シートを書かなければ `sheets` の最初か、ブックの最初のシート。`key` / `columns` / `where` とは一緒に使えない |
| 更新日時とサイズだけ（ファイル） | `watch: timestamp` | 中身は問わず、保存されたかどうかが分かればよいとき。ファイルはコピーも開きもしない（大きいファイルや、テキストにできない形式でも軽い）。`max_size_mb` は当てはまらない |

見張り方を変えると、前の履歴とは比べられないので基準を取り直す（下の「決まりごと」）。

### ルールと期限（要注意）

変わったところとは別に、「こうなっているはず」を決めておくと、合わないものを「要注意」として出す。チェックのたびに watchpoint が決まったとおりに確かめるので、AI は使わず、何も外に送らない。元の資料が直されれば消える（確認済みにしても消えない）。新しい要注意は一度だけ通知する。

| 決められること | 例 | 出方 |
|---|---|---|
| 更新の期限（どの見張りにも） | `毎週金 17:00`・`平日 9:00`・`毎日 9:00`・`毎月25日 17:00`・`3d` | `11/27 17:00（毎週金 17:00）までに更新されていません（最後の変更 11/18 10:02）` |
| 空にしない | 承認・回答の欄 | `No. 2: 回答 が空です（状態 が 回答済）` |
| 決まった値のどれか | 状態は 未回答・回答済 のどれか | `No. 3: 状態 が「保留」です（未回答・回答済 のどれかのはず）` |
| 決まった形（正規表現） | 日付は 2026-11-27 の形 | `No. 5: 期限 の「来週」が決めた形に合いません` |

- 値のルールは、行ごとに見る見張り（key のある Excel・CSV・JSON）と、決まったセルの見張りに付けられる。「状態 が 回答済 の行だけ」のような条件と、警告の文言（「承認漏れ」など）も付けられる
- **画面**: 見張りの「ルールと期限」で作る。期限はよくある形から選ぶか自分で書く。値のルールは、列を選ぶと「5 行中 2 行が空（No.3・No.4）／値: 未回答（2）・回答済（1）」のようにいまのデータの様子が出て、足す前に「このルールだと、いま 1 件が引っかかります」と見せる
- **CLI**: `watchpoint fields <name>`（列ごとの空の数と値の種類）、`watchpoint rule add <name> --field 回答 --required --when 状態=回答済 [-m 回答漏れ] [--dry-run]`、`rule list`、`rule remove`、`watchpoint expect <name> "毎週金 17:00"`（`--clear` でなくす）。設定ファイルは、そのルールの部分だけを、誤りを確かめてから書き換える（前の内容は `.bak`）
- **AI に相談**: スキルを入れたエージェントに「回答漏れがあったら警告してほしい」と頼むと、データを見て根拠付きの案を出し、いま何件が引っかかるかを見せ、本人が決めてから足す
- 期限は、チェックのときに確かめるので、チェックの間隔の分だけ遅れて出ることがある。見張り始める前の期間は分からないので、警告しない
- 「重要そうな変更なら」のような決まった規則にできない判断は、ルールではなく「知らせる条件」（AI が読む指示）に書く

## 入れる

```powershell
uv tool install C:\path\to\watchpoint
```

開発中は、このフォルダで `uv run watchpoint ...` でも動く。

### AI エージェントから使う（スキル）

Copilot CLI や Claude Code などの AI エージェントに「watchpoint の見張りを全部チェックして要約して」と頼めるように、スキル（エージェント向けの手順書 `SKILL.md`）を入れる。

```powershell
uv tool install C:\path\to\watchpoint   # どこからでも watchpoint を動かせるようにする（エージェントはこれを呼ぶ）
watchpoint skill install                 # ~/.agents/skills（Copilot CLI ほか）と ~/.claude/skills（Claude Code）に入れる
```

- スキルの中身は `watchpoint skill show` で見られる（原本はこのリポジトリの `src/watchpoint/skill/SKILL.md`。watchpoint に同梱されるので、どこに入れても `skill install` で写せる）。エージェントは、チェックして各見張りの読むポイントに沿って要約し、頼まれたときだけ `--seen` 付きで確認済みにする。設定ファイルの書き換え、コマンドの許可（`allow`）、タスク スケジューラの登録はしない
- `--to agents` / `--to claude` で片方だけ、`--dir .github/skills` でリポジトリの中に入れる。watchpoint を新しくしたら、もう一度 `watchpoint skill install`（スキルも同じ版に更新される）
- 自分で書いた同じ名前の `SKILL.md` は上書きしない（`--force` のときだけ）。`watchpoint skill uninstall` で消せる（watchpoint が入れたものだけ）
- エージェントに頼むと、変更の中身はそのエージェントのサービスに送られる。画面の「AI 用にコピー」と違い、元のファイルの場所なども含まれる

## 試してみる（デモ）

自分のファイルを使わずに、どう見えるかを試せる。見本の Excel・ファイル・フォルダと、この PC の中だけで出す Web ページを `%TEMP%\watchpoint-demo` に作り、専用の設定で窓を開く（自分の設定やデータには触らない）。

1. `demo\start.bat` をダブルクリック（窓が開く）。「すべてチェック」を押して、いまの状態を基準にする
2. `demo\change.bat` をダブルクリック。見本に変更を起こす（押すたびに次の変更）
3. 窓で「すべてチェック」を押すと、6 つの見張りに変更が出る

| 見張り | 起こす変更 | 出方 |
|---|---|---|
| 質問表（自分の行） | 自分の行の状態と回答、自分宛ての質問を追加。ほかの人の行も書き換える | `変更 [No.=1] 状態: 未回答 → 回答済`・`追加 [No.=4] …`。ほかの人の行は `where` で外れるので出ない |
| 集計（合計と承認） | 合計のセルと承認欄 | `変更 [セル=C6] 合計: 120 → 135`・`承認: (空) → 山田` |
| 仕様書 | 数字の書き換えと1行追加 | 差分。変わった語（`30` → `90`）は行の中で強調される |
| 議事録フォルダ | ファイルを追加 | `追加 [ファイル=…_定例.txt]` |
| 提案書（保存されたかだけ） | 上書き保存 | サイズと更新日時の変化だけ（中身は開かない） |
| お知らせページ | お知らせを追加。閲覧数も変える | 追加したお知らせだけ。閲覧数は見る部分（`selector: main`）の外なので出ない |
| コミット履歴（コマンド） | 履歴にコミットを 1 件足す | 初めは「まだ許可していないコマンド」と出るので、「このコマンドを許可する」を押す。そのあとは `追加 [rev=r3] author=… \| message=…`。許可したものは「設定」の下の「許可したコマンド」に出る |

やり直すときは窓を閉じて `demo\reset.bat`。

## 使う

```powershell
watchpoint init                  # 設定ファイルのひな形を作る（~/.watchpoint/targets.yaml）
watchpoint doctor [--fetch]      # 設定・場所・資格情報・通知先を確かめる（保存しない）
watchpoint list [-t タグ]         # 見張りの一覧（name・比べ方・タグ・間隔・場所）
watchpoint preview 質問表         # テキストにした結果だけを見る（保存も比較もしない。設定を試すとき）

watchpoint check                 # 全部を取ってきて比べる
watchpoint check 質問表 -t 案件A   # name の一部、タグで絞る
watchpoint check -f md -C        # AI に読ませる形で、変更あり・取得失敗だけ（-f json はプログラム向け）
watchpoint check --due           # every の間隔が過ぎた見張りだけを取りに行く
watchpoint check --notify        # 新しい変更と取得失敗を、notify の drop_folder に知らせとして置く
watchpoint ack [質問表] -m "メモ"  # 出た変更を確認済みにする（メモは history に残る）
watchpoint ack 質問表 --seen <番号>  # 見た時点までを確認済みに（その後に届いた変更は残す。番号は -f md / json に出る）

watchpoint status                # 最後の結果・未確認の変更・次の予定（取りに行かない）
watchpoint diff 質問表            # 未確認の変更。--from 3 --to 1 で任意の履歴どうし
watchpoint history 質問表         # 履歴の一覧（番号は diff / show で使う）
watchpoint show 質問表 -g 2       # 履歴のある時点のテキスト
watchpoint open 質問表 --place   # 見張っている場所を開く（ファイルはフォルダで選ぶだけで、開かない）
watchpoint open 質問表            # 最後に取ってきたコピーを開く（元のファイルは開かない。--text でテキスト）
watchpoint allow docs             # コマンドの出力を見張る見張りの、コマンドを確かめて許可する
watchpoint log [-n 50]           # これまでの check と ack の記録
watchpoint gui                   # 専用の窓で見る（下の「画面」。--browser でブラウザ）
watchpoint schedule install      # 5 分おきに自動でチェックして知らせる（下の「自動で見張る」）
watchpoint clean [--yes]         # 設定から消した見張りのデータを片付ける

watchpoint secret set redmine    # API キーやトークンを登録（Windows の資格情報マネージャー）
watchpoint secret check redmine  # 登録されているか（値は出さない）
watchpoint secret delete redmine
```

### 画面

`watchpoint gui` で、専用の窓に次の画面が開く。窓を閉じると終わる。

ふだんはリポジトリの `gui.bat` をダブルクリックすればよい（デスクトップにショートカットを置いておくと楽）。足りないライブラリをそろえてから窓だけを開き、黒い窓は残らない。設定ファイルを分けるときは `gui.bat -c D:\work\targets.yaml` のように引数を渡す。

- 上: 未確認と取得失敗の件数（窓やタブの題名にも出る）、自動チェックの様子（止まっていれば赤で出る）、チェック中の進み具合（何件目か、いまどの見張りを取っているか）
- 左: 見張りの一覧（状態、未確認の変更の印、最終チェック、次回の予定）。名前・タグ・「未確認の変更と取得失敗だけ」で絞れる。表示中の未確認をまとめて確認済みにできる。確認済みにするのは画面に出ている世代だけで、その間に自動チェックなどで新しい変更が届いていたら、その見張りは確認済みにせずに知らせる
- 右: 選んだ見張りの元の場所と、その場所へ飛ぶボタン（下の「場所を開く」）、チェックの間隔（その場で変えられる。設定ファイルの `every` の行だけを書き換え、コメントやほかの行はそのまま）と次回の予定、未確認の変更、読むポイント、履歴の一覧。未確認の変更は、行ごとに見る見張りなら表で出す。既定は「元の表の形」で、変わった行だけを元の列の並びで出し、変わったセルに前と後を重ねる（同じ行の質問などが隣に見える。列が 10 を超えるときは、変わった列と左の 3 列を残して畳む）。「変わった項目だけ」に切り替えると、行・項目・前・後の表になる。どちらも追加・変更・削除と項目で絞れ、多いときは「すべて表示」。文章なら差分で、行の中の変わった語を強調する。長い変更は画面の高さの 6 割ほどの枠の中でスクロールするので、下のルールや履歴にもすぐ届く。大きな変更は「全画面で見る」（`f` キー）で、変更だけを窓いっぱいに出して読める（そこで確認済みにもできる。`Esc` で戻る）
- 選んで操作する: 一覧の各行のチェックボックス（Ctrl+クリック、Shift+クリックで範囲、`x` キーでも）で選ぶと、一覧の上に「N 件を選択中」のバーが出て、選んだものだけをチェック・確認済みに・AI 用にコピーできる。上の「すべてチェック」も「選択した N 件をチェック」に変わる。選んだものは一覧を絞っても残り、隠れた分は「表示外」と出る。Esc で解除。停止中の見張りは選べない
- 絞って操作する: 名前・タグ・「未確認の変更と取得失敗だけ」で一覧を絞ると（何も選んでいないとき）、「すべてチェック」が「表示中の N 件をチェック」に変わり、出ている見張りだけをチェックする（「時間が来たものだけ」と「AI 用にコピー」も、出ている分だけが対象）。案件ごとにタグを付けておけば、タグを押すだけでその案件だけをチェックできる
- できること: すべて / 時間が来たものだけ / 1件をチェックする、メモを付けて確認済みにする、任意の履歴どうしを比べる、ある時点のテキストを見る、いまの内容をテキストで見る（保存しない）、取ってきたコピーを開く（文書・表・PDF・画像は関連付けのアプリで。スクリプト・プログラム・ショートカット・マクロ付きの形式・Web ページは実行しないよう、エクスプローラーで場所を示すだけ）、check と ack の記録を見る
- **AI 用にコピー**: 未確認の変更と取得失敗を、AI のチャットに貼る文章にする（取りに行かず、保存してある状態から作る）。watchpoint が自分で AI に送ることはない。貼るのは本人
  - 押すと、まず貼る文章をそのまま見せる（件数と文字数も）。中を確かめてから「コピー」。長すぎるときは、選ぶか絞り込むと短くなる
  - 要約に要らないものは入れない: 手元のファイルの場所や、確認済みにするコマンドは入れない。元のファイルの場所（共有フォルダのパスや URL）も、チェックを入れたときだけ
  - AI の要約を読み終えたら、同じ画面の「読み終えた N 件を確認済みにする」で確認済みにする。確認済みになるのはコピーした時点の変更だけで、そのあとに届いた変更は残る（ログにメモ「AI で要約して確認」が残る）
  - AI エージェント（コマンドを動かせる AI）に読ませるときは `check -f md -C`。こちらは、確認済みにするコマンドなど、エージェントが動くのに要る行も入る
- **開いている間、自動でチェック**: 画面を開いている間、各見張りをそれぞれの間隔（every。既定 30 分）でチェックし（1 分ごとに、間隔が過ぎた見張りがないかを見る）、新しい変更や取得失敗を Windows の通知で知らせる（押すとその見張りを開く。窓が後ろにあればタスクバーも点滅する。ブラウザで開いたときは、初回にブラウザが通知の許可を聞く）。画面を閉じると止まる。この設定は次に開いたときも残る
- **見張りを追加**（一覧の上と「設定」の中。見張りがひとつもないときは最初の画面に出る）: 場所を入れる（「ファイル…」「フォルダ…」で Windows の選択画面からも選べる。前後の `"` は外す）と、種類を見分けて中を見る。Excel / CSV はシートの先頭の行を表で出し（コピーを取って読む。元のファイルは開かない）、次をクリックで選べる
  - **中身の変化**: 見出しの行（推測して出す。違えば行番号をクリック）、行を見分ける列（値が埋まっていて重ならない列を「おすすめ」として出す）、見る列（見出しをクリックで外す）、この行だけ（列の値から選ぶ。`vars` の値と同じ値があれば「自分の行だけを見張りますか？」と聞く）
  - **決まったセルだけ**: セルをクリック（ドラッグで範囲）。名前は左か上の見出しから付ける（「合計」など）。表に出ないセルは番地でも足せる
  - **保存されたかだけ**: 中身は開かず、更新日時とサイズだけ
  - **SharePoint の Excel**: URL を入れると「Excel で取ってきて表を出す」が出る。押すと、チェックのときと同じく見えない Excel が読み取り専用で開いてコピーを保存し（ふだんの Office のサインインを使う）、そのコピーで表を出す。Excel で取れないときは「ダウンロードしたファイルを選ぶ…」で、手で落としたコピーを見本にしてもよい。どちらも表を出すためだけに使い、設定には URL だけを書く。見本が古くても、「試しに取り出す」は URL から本物を取ってくるので、選んだシートや列が本物に無ければそこで分かる
  - その種類に使えない見張り方は選べない。名前は場所から付け（重なれば「（2）」）、間隔・知らせる変化・知らせる条件は「名前・間隔・知らせ方」に畳んである。選んだ内容は「「質問表」として、「質問一覧」シートの 3 行を、「No.」で行を見分けて見張ります…」のように文で出る
  - 「試しに取り出す」で、保存せずに取ってきて、比べる中身と「変わったときの知らせの例」を見られる。「見張りを始める」で設定ファイルに書き足して保存し（前の内容は `.bak`、コメントやほかの見張り・改行・BOM はそのまま）、すぐに 1 回確かめて基準を取る。設定の編集欄に保存していない変更があるときは、そこに書き足すだけにする
  - 入れた内容があるうちに閉じる（Esc でも）と、捨ててよいか聞く
- **場所を開く**: 「元の場所」の横のボタンで、見張っている場所へ飛ぶ。ファイルは「フォルダで開く」（エクスプローラーでそのファイルを選んだ状態でフォルダを開く。ファイル自体は開かない）、フォルダはそのフォルダ、Web ページと Confluence はそのページ。SharePoint の Excel・Word は、ファイルの URL を開くと元のファイルを編集できる状態で開いてしまうので、既定では開かない。見張りごとに `link:`（URL かパス）を書くと、どの見張りでもそこを開く（SharePoint ならそのフォルダの URL など）。`link:` は「見張りを追加」の「名前・間隔・知らせ方」でも入れられる
- **見張りを削除**: 見張りの「その他」の「この見張りを削除…」で、設定ファイルからその見張りだけを消す（すぐ上に付けたコメントも一緒に消す。前の内容は `.bak`）。取った履歴は既定で残し、同じ名前で足し直すと続きから見られる。「取った履歴も消す」を選んだときだけ消す（元に戻せない）。チェック中は消せない。`include` で取り込んだ見張りは、そのファイルで消す
- **チェックの経路**: 履歴とログに、そのチェックを何が始めたか（画面で押した・画面の自動・タスク スケジューラ・ターミナル・追加したとき）を出す。変更が、自分で押して見つかったのか、自動で見つかったのかが分かる
- **設定**: 設定ファイルをその場で直せる。打つのを止めると誤りを確かめ、「保存前の内容で試す」で保存前の内容のまま見張りを取ってきてテキストにできる（key・where・columns を合わせるとき）。誤りのある内容は保存しない。保存すると前の内容を `.bak` に残し、改行（CRLF）と BOM は元のファイルに合わせる。画面で開いたあとにほかで書き換えられていたら、上書きせずに知らせる
- キー: `j` / `k` で移動、`c` でチェック、`a` で確認済みに、`/` で絞り込み、設定では `Ctrl+S` で保存
- ブラウザで開いたときは、URL の `#` の後ろが選んでいる見張りの name なので、ブックマークできる

**専用の窓**は、Windows に入っている Edge の部品（WebView2）を使う。画面は Python から直接渡し、画面からの操作も Python を直接呼ぶので、ポートを開かず、サーバーも立てない。ふだん使うブラウザとは別物なので、ブラウザの拡張機能・ほかのタブ・保存したサインインからは見えず、触れない。窓の中は外へ一切通信できない（Content-Security-Policy）。WebView2 は Cookie やキャッシュを残さず、覚えておく設定（自動で確かめるか）だけを設定ファイルの隣の `window.json` に書く。WebView2 が無い PC では、ブラウザで開く。

**ブラウザで開く**（`watchpoint gui --browser`）ときは、この PC の中（127.0.0.1）でだけ待ち受け、ほかの PC からはつながらない。起動するたびに合言葉を作り、ターミナルに出す URL（`?k=` 付き）に一度だけ載せる。開くと合言葉は Cookie（HttpOnly・SameSite=Strict）に移り、アドレス欄からは消える。合言葉を持たない要求は画面も API も断るので、同じ PC のほかのプログラムやほかのユーザーがポート番号を知っていても、同じブラウザで開いているほかのサイトからも操作できない。ページの中のスクリプトはこの画面のものだけが動き、外へは通信しない（Content-Security-Policy）。`check` と `ack` は、ターミナルと同じ同時実行の決まりに従う（どちらかが動いていれば待つ）。外部のライブラリや CDN は使わない（社外につながらない環境でも動く）。

`--browser` と一緒に `--port 8800` で使うポートを決められる。`--no-browser` はサーバーだけを立てて URL を出す。止めるときは、起動したターミナルで Ctrl+C。

### 自動で見張る

```sh
watchpoint schedule install [--every 5]   # タスク スケジューラに登録して、すぐ1回動かす
watchpoint schedule status                # 登録されているか、最後にいつ動いてどうだったか
watchpoint schedule remove                # 登録を消す（取ってきたコピーや確認済みの状態は残る）
```

Windows のタスク スケジューラに、自分のユーザーで動くタスクを登録する。管理者権限もパスワードも要らない代わりに、サインインしている間だけ動く。毎回 `check --due --notify` と同じこと（期限の過ぎた見張りだけを取りに行き、新しい変更を `drop_folder` に知らせとして置く）をし、確認済みにはしない。

- 画面は出ない（`pythonw` で動く）。出力は `data_dir` の `scheduled.log` に残る
- 動くたびに `data_dir` の `heartbeat.json` に結果を残す。`status` と画面の上に「最後にいつ動いたか」が出て、間隔の 3 倍を過ぎても動いていなければ赤で知らせる（何も知らせが来ないのが「変化なし」なのか「止まっている」のかを区別するため）
- 設定ファイルの誤りなどでチェックできなくなったら、一度だけ知らせを置く（エラーの文が回ごとに変わっても繰り返さない）。直って動き出したら、もう一度知らせる。前の回が終わらずに止められた（30 分）ときも知らせる
- 設定ファイルが壊れていても知らせが届くよう、最後に読めたときの `data_dir` と `drop_folder` を `%LOCALAPPDATA%\watchpoint` に覚えておく
- 画面や手で `check` している間に動く番になったら、その回は見送る（次の回で取り戻す）
- 登録する間隔（`--every`、既定 5 分）は、見回りの細かさ。各見張りは、それぞれの `every`（既定 30 分）が過ぎたときだけ取りに行く
- `log.jsonl` は 5 MB を超えたら `log.1.jsonl` に回す

`check --exit-code` を付けると、終了コードで結果を返す（0: 変更なし / 1: 変更あり / 3: 取得失敗のみ）。ほかの終了コード: 2 は設定の誤り、4 はほかの watchpoint が動いていて待ちきれなかった。

## 決まりごと

- **元のファイル（マスター）を守る**: 元のファイルをアプリで開いたり、書き込み用に開いたりはしない
  - ファイル（Excel・Word・CSV・テキスト）は、読み取り専用でコピーを取り、そのコピーだけを読む。コピーしている間も、持ち主は保存・名前の変更・削除ができる（使用中で保存できない、にならない）。コピーの途中で保存されたら、そのコピーは捨てて取り直す
  - 「保存されたかだけ」とフォルダは、日時と大きさを見るだけで、中身は開かない
  - `fetch: office` は、SharePoint の URL だけを Excel・Word に読み取り専用で開かせる（マクロは動かさず、元は保存せずに閉じる）。共有フォルダや手元のファイルは、先にコピーを取り、Excel・Word にはそのコピーを開かせる
  - 同じファイルを見る見張りが複数あっても（同じ Excel の B 列と G 列など）、1 回のチェックで取ってくるのは 1 回だけ（Office 経由・Web のファイル・Confluence の添付）。見えない Excel の起動も、サインインが要るときの待ち時間も 1 回で済む。取れなかったときは、そのファイルを見るどの見張りも同じ理由の取得失敗になる
  - 画面の「保存したコピーを開く」と `watchpoint open` は、履歴に残したコピーでもなく、一時フォルダに作った読み取り専用の 3 つ目のコピーを開く（名前に「読み取り専用」と付く）。うっかり編集しても、元のファイルにも履歴にも保存されない。開くと何かが動く形式（スクリプト・プログラム・マクロ付きの形式など）は、開かずにエクスプローラーで場所を示す
  - Web・API・Confluence は読む（GET）だけ。コマンドは読むだけと分かっているものだけ
- **確認済みの基準**: 変更は、最後に `ack` した時点の内容と比べる。`ack` するまで同じ変更を出し続ける。取得に失敗している間も、前に取った未確認の変更は出し続ける
- **未確認の変更は消さない**: 未確認の変更があるうちに設定を変えると、新しい基準とは比べられないので、その変更を「設定を変える前の未確認の変更」として取りのけ、`ack` するまで履歴から消さずに出し続ける（`keep` が小さくても消えない）
- **元に戻った変更**: 内容が変わってから確認済みと同じ内容に戻ったときも、「確認済みと同じ内容に戻りました」として、途中の版での変化と一緒に出す（途中の変化を見て、だれかが動いたかもしれないため）。`ack` すると消える
- **見るだけでは何も変えない**: 履歴の比べ直し（`diff --from --to`、画面の履歴）や画面の表示は、保存した写しや差分を書き換えない。差分を残すのはチェックだけで、何と比べた差分かも一緒に残す
- **条件外の変化**: `report` や `match` に当たらない変化は「条件外の変化」とし、自動で確認済みにする（関係ない変化がたまらない）
- **基準の取り直し**: `source`・`key`・`where`・`sections`・`cells`・`watch` など、テキストの作り方を変えると前の履歴とは比べられないので、基準を取り直す（そのときは「初回」）
- **取り直し**: コピーの間にファイルが変わった（だれかが保存中）、または読めない形で壊れていたら、2 秒待って 1 回だけ取り直す
- **取得の省略**: ファイルはサイズと更新日時、Confluence Cloud は版番号が前回と同じなら、取りに行かない
- **同時実行**: `check` と `ack` は同時に 1 つしか動かない（人と AI が同時に実行しても状態が壊れない）
- **失敗の扱い**: `fail_after: 3` なら、3 回続けて失敗するまでは「一時的に取得できず」とし、取得失敗として出さない
- **通知**: 同じ未確認の変更については 1 回だけ。取得失敗は、続いた失敗につき 1 回だけ。要注意は、新しく出たものを 1 回だけ（直ってからまた出たら、もう一度）。「見つけた」と「知らせた」は別に残すので、通知しないチェック（画面のチェックなど）で先に見つけたものや、通知先に書けなかったもの（`log` に「通知できず」と残る）も、次に通知するチェックで知らせる
- **名前を変える**: name を変えると別の見張りになる。履歴を引き継ぐなら `id` を付けておく。大文字小文字や記号だけが違う name は、Windows では同じフォルダになるので設定の誤りにする
- **Office 経由の取得**: 見えない Excel / Word の中でサインイン画面が出ると止まったままになるので、`timeout`（既定 120 秒）を過ぎたら、その取得のために起動した Excel / Word だけを終わらせる（いつも使っている Excel には触らない）
- **Web・API**: 接続が切れた、または 429 / 502 / 503 / 504 のときは、1 回だけ取り直す（Retry-After があれば最大 30 秒待つ）。応答に文字コードが書かれていないページは、ページの `<meta charset>` に従う（文字コードを応答に書かない Shift_JIS のページ向け）
- **フォルダ**: Office のロックファイル（`~$`）、`Thumbs.db`、`desktop.ini`、`.tmp`、ダウンロード途中のファイルは一覧に入れない
- **チェックの間隔**: 自動のチェック（タスク スケジューラ、画面の「開いている間、自動でチェック」、「時間が来たものだけ」、`check --due`）は、前回から `every` が過ぎた見張りだけを取りに行く。`every` を書かない見張りは、設定の一番上の `every`（既定 30 分）になる。5 分より短い間隔は、取りに行く先（共有フォルダ・Web・Confluence）の負担になるので設定の誤りにする。手で押したチェックと、名前を指定した `check` は、間隔に関係なくいつでも動く
- **チェックする時間帯**: `check_hours` を書くと、自動のチェックはその時間帯だけ動く（夜や週末に見張る先へ取りに行かない）。時間外のあいだは画面の上に「時間外（次は … から）」と出て、「次回」も時間帯の始まりにずれる。手で押したチェックはいつでも動く
- **届かない場所**: 共有フォルダに届かない・アクセスを断られる見張りがあっても、設定は読み込み、その見張りだけを取得失敗にする（ほかの見張りは動く）
- **壊れた状態**: `state.json` が壊れていたら `state.broken-<日時>.json` に退避して、最初からやり直す

## 設定

```yaml
every: 30m            # 自動チェックの間隔（見張りごとの every が無いとき）。5m より短くはできない
check_hours:          # 自動チェックをする時間帯（書かなければいつでも）。手で押すチェックには効かない
  days: 平日          # 平日 / 毎日 / 土日 / [月, 水, 金]
  time: '9:00-19:00'  # 引用符で囲む（YAML が 9:00 を数として読むため）。日をまたぐ時間帯は書けない
keep: 5               # 残しておく履歴の数（確認済みの基準と最新は消さない）
max_diff_lines: 300   # 1件あたりに出す変更の行数の上限
keep_originals: true  # false にすると原本は残さずテキストだけ（容量の節約）
workers: 4            # 並べて取ってくる数
data_dir: '%LOCALAPPDATA%\watchpoint\data'   # 取ってきたコピーの置き場所（既定はこのファイルの隣の data）。設定を共有フォルダに置くときは手元に

vars:
  me: 佐藤             # ${me} で参照できる（source・where・points など）

include: [targets.d/*.yaml]   # 見張りを別のファイルに分ける（そのファイルには targets だけを書く）

notify:
  drop_folder: '%LOCALAPPDATA%\Notifier\queue'   # 1件 = 1つの JSON（下の形式）
  on_failure: true

targets:
  - name: 質問表（〇〇案件）
    id: q-maru                # 省略すると name。name を変えても履歴を引き継ぐときに付ける
    source: '\\server\share\project\質問表.xlsx'   # %USERPROFILE% や ~ も使える
    tags: [〇〇案件]
    every: 1h                 # この見張りだけ間隔を変える（30m / 2h / 1d。書かなければ上の every）
    link: '\\server\share\project'   # 画面の「場所を開く」で開く先（URL かパス。書かなければ、ファイルはそのフォルダ）
    expect_update: 毎週金 17:00       # この時刻までに更新されていなければ「要注意」（平日 9:00 / 毎月25日 17:00 / 3d など）
    rules:                            # 合わない行を毎回「要注意」として出す（画面の「ルールと期限」でも作れる）
      - field: 回答
        required: true                # 空にしない
        when: {状態: 回答済}           # この行だけ
        message: 回答漏れ              # 警告の文言（省略すると自動）
      - field: 状態
        one_of: [未回答, 回答済]       # このどれか（pattern: で正規表現も）
    sheets: [質問一覧]         # 省略するとすべてのシート
    header_row: auto          # 見出しの行（数字か auto。auto は key の見出しがある行を探す）
    key: No.                  # 行を見分ける列
    columns: [質問, 回答者, 状態, 回答]   # 見る列（省略するとすべて。見出しが空の列も、値があれば「G列」の名前で見る）
    where:
      回答者: ${me}            # この文字を含む行だけ（[佐藤, 鈴木] で複数も可）
    formulas: false           # true にすると、値ではなく数式を比べる
    report: [added, changed]  # 数える変化の種類（added / changed / removed）
    fail_after: 3
    points: |
      追加された行は新しい質問。それぞれの要旨を1行で。
      状態が変わった行は、何から何に変わったかを挙げる。
    notify_when: 自分宛ての新しい質問があるとき

  - name: 集計表の合計
    source: '\\server\share\project\集計.xlsx'
    cells:                    # このセルだけを見る（範囲は B3:D5）
      合計: 集計!F20
      承認: 表紙!C5

  - name: 設計書の更新
    source: '\\server\share\project\設計書.pdf'
    watch: timestamp          # 中身は開かず、更新日時とサイズだけを見る

  - name: 仕様書
    source: '\\server\share\project\仕様書.docx'
    sections: [ログ, 画面]     # この見出しの下だけを見る
    include: ['保持|保存']     # この正規表現に当たる行だけを見る
    ignore: ['^最終更新']      # この正規表現に当たる行は比べない
    normalize: [whitespace, nfkc]   # 空白の違い・全角半角の違いを無視（case で大文字小文字も）。行ごとに見る見張りでは値だけを直し、列名はそのまま（ルールの値も同じように直して比べる）
    sort_lines: false         # true にすると、見出しの下の行の順番の違いを無視
    match: ['〇〇機能']        # 変わった行にこの正規表現が当たるときだけ「変更あり」
    max_size_mb: 50

  - name: 議事録フォルダ
    source: '\\server\share\project\議事録\*.docx'   # サブフォルダも見るなら **\*.docx と recursive: true
    report: [added]

  - name: お知らせページ
    source: https://example.com/news
    selector: '#main'
    remove: ['.views', '.ad']

  - name: 設計ページ
    source: https://confluence.example.com/pages/viewpage.action?pageId=123456
    auth: {type: bearer, secret: confluence}   # Server / Data Center の個人用アクセストークン
    # Cloud なら auth: {type: basic, user: me@example.com, secret: atlassian}

  - name: 自分の不具合チケット
    source: https://redmine.example.com/issues.json?assigned_to_id=me&tracker_id=1&status_id=*&limit=100
    paginate: offset
    key: id
    columns: [subject, status.name, priority.name, 辛さ, 味見, updated_on]
    auth: {type: header, header: X-Redmine-API-Key, secret: redmine}

  - name: SharePoint の質問表
    source: https://contoso.sharepoint.com/sites/team/Shared%20Documents/質問表.xlsx
    fetch: office             # Excel に読み取り専用で開かせる（1回ごとに Excel が起動するので every: 30m などに）
    key: No.
```

チケットの一覧（Redmine の `issues.json` など）のこつ:

- 一覧が1つだけの JSON なら `records` は書かなくてよい（`issues` を見つける）。
- `status_id=*` にすると、完了にしたチケットも一覧に残り、「状態: 対応中 → 完了」と出る。`status_id=open`（既定）だと、完了にしたチケットは一覧から消えるので「削除」と出る。
- カスタムフィールドは、その名前の項目になる（`辛さ=中辛`）。`columns` やルール（`--field 辛さ`）にそのまま書ける。ふつうの項目と名前がぶつかるときだけ `custom_fields.<名前>` になる。ユーザーやバージョンのカスタムフィールドは、名前ではなく番号で出る。
- 絞り込みは、ブラウザでチケット一覧を絞ったときの URL の `/issues?` を `/issues.json?` に変えて使える（`f[]=cf_12&op[cf_12]==&v[cf_12][]=辛口` のような条件もそのまま効く）。
- API キーは Redmine の「個人設定 → API アクセスキー」にある。REST API が有効になっていれば、管理者の権限は要らない。
- コメント（注記）の中身は見ない（一覧の API に入っていないため）。変わったことは `updated_on` で分かる。中身は AI に Redmine の読む道具で読ませるとよい。

Web・API の共通の項目: `headers`（足すヘッダー）、`timeout`（秒、既定 30）、`verify`（true: Windows の証明書ストアを使う / false / CA ファイルのパス）。プロキシは環境変数 `HTTPS_PROXY` に従う。

資格情報は設定ファイルに書かない。`watchpoint secret set <名前>` で Windows の資格情報マネージャーに置き、`auth: secret` でその名前を指す（環境変数 `WATCHPOINT_SECRET_<名前>` があればそちらを使う）。貼り付けで付いた前後の空白は落とし、改行・タブなどの入った値は断る。エラーの文やログに資格情報の値は出さない。URL の `?key=` に資格情報を書くと、URL ごとエラーの文や記録に出るので、`auth` を使う。

別のサイトへ転送されたときは、資格情報（`auth`）や `headers` を送らずに止める。同じサイトの別のページ（ログインの画面など）へ転送されたときも、その画面を比べずに取得失敗にする（転送先が正しいなら `source` をその URL にする）。応答は 1 回につき 50 MB まで、時間は `timeout` の 3 倍（最短 30 秒）までで打ち切る。

### 知らせの形式（v1）

`check --notify` は、`drop_folder` に1件1ファイルで次の JSON を置く。`.` で始まる名前で書き切ってから名前を変えるので、読む側が書きかけを見ることはない。

```json
{"v": 1, "type": "notify", "text": "質問表: 追加 1 / 変更 0 / 削除 0 件…", "source": "watchpoint"}
```
