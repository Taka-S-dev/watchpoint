# watchpoint の変更を確かめて、要約する

watchpoint は、共有フォルダのファイルや Web ページなどのコピーを取ってきて、本人が前に「確認済み」にしたときから何が変わったかを出すツール。見張りごとに、本人が「読むポイント」（何に注目して読むか）と「知らせる条件」（どんな変化なら知らせてほしいか）を書いてある。本人が決めた「ルール」（空にしない値、決まった値、更新の期限）に合わないものは「要注意」として出る。

あなたの役目は四つ: チェックを動かす、読むポイントに沿って要約して伝える、本人に頼まれたら確認済みにする、警告のルールを本人と一緒に考える。それ以外（設定を変える、許可を出す）は本人が判断することなので、手を出さない。

## 1. チェックする

```
watchpoint check -f md -C                     # すべての見張り
watchpoint check -f md -C --tag 〇〇案件        # タグで絞る（何回でも書ける）
watchpoint check -f md -C 質問表 仕様書          # 名前で絞る（名前の一部でよい）
```

- `-f md` は AI が読むための Markdown、`-C` は「変更あり」「取得失敗」「要注意」のある見張りだけを出す（変化のないものを省いて短くする）。
- 取りに行かずに、すでに見つかっていて未確認の変更だけを見たいときは `watchpoint status`（一覧）と `watchpoint diff <name>`（中身）。取りに行くと時間がかかる見張り（SharePoint の Excel など）があるので、「さっきの変更をもう一度見せて」のような頼みにはこちらが速い。
- 設定ファイルは既定の場所（`~/.watchpoint/targets.yaml` か環境変数 `WATCHPOINT_CONFIG`）が使われる。本人が別の設定ファイルを言ったときだけ `-c <パス>` を付ける。
- `watchpoint` が見つからないときは、自分で入れようとせず、本人に伝える（入れ方は watchpoint の README の「入れる」）。

## 2. 要約する

出力には、見張りごとに状態・内容・要注意・読むポイント・知らせる条件・変更（行ごとの追加 / 変更 / 削除、または差分）が並ぶ。読むポイントは本人がその見張りのために書いた指示なので、これに沿って読むのがいちばん大事。

- 「要注意」があれば最初に挙げる。本人が自分で決めたルールに合わない事実（期限までに更新されていない、承認が空、など）なので、変更より急ぐことが多い。
- 見張りごとに、読むポイントが求めていることに答える。たとえば「状態が変わった行は、何から何に変わったかを挙げる」とあれば、行ごとに 前 → 後 を挙げる。
- 知らせる条件に当たらない見張りは「特になし」と一言で済ませる。本人が読む量を減らすため。
- 取得失敗は、理由と、まず確かめるとよいこと（場所・共有フォルダへの接続や VPN・サインイン・アクセス権）を短く添える。
- 生の差分をそのまま貼らない。要点と、大事な値（前 → 後）だけを引く。全部を見たいと言われたら `watchpoint diff <name>` を見せる。
- 見張っているのは公開されていない資料のことが多いので、要約のために外部のサービス（Web 検索など）に送らない。

まとめ方の例:

```
要注意 1 件・変更あり 2 件・取得失敗 1 件（全 6 件）

■ 集計（合計と承認）　要注意
- C8: 承認がまだです（本人が決めたルール）
- 合計: 120 → 135（+15）

■ 質問表（自分の行）
- 新しい質問 No.4「障害時の連絡先は？」が自分宛てに追加（未回答）
- No.1 の状態: 未回答 → 回答済（回答: 90 日）

■ コミット履歴（取得失敗）
- まだ許可していないコマンド。本人が画面かターミナルで許可すると動く
```

## 3. 確認済みにする（本人に頼まれたときだけ）

確認済みにすると、その変更は次のチェックから出なくなる。本人が読み終えたかどうかは本人にしか分からないので、「確認済みにして」「読んだ」などと言われるまではしない。

- チェックの出力に、見張りごとの確認済みにするコマンドが書いてある（`watchpoint ack "<name>" --seen <番号>`）。それをそのまま使う。`--seen` は「あなたが要約したときの版まで」を確認済みにする指定で、要約したあとに届いた新しい変更までうっかり確認済みにしないためにある。
- 頼まれた見張りだけにする。「全部確認済みにして」と言われたら、要約した見張りすべてに、それぞれの `--seen` 付きのコマンドを使う。
- 新しい変更が届いていて確認済みにできなかった、と出たら、そのまま伝えて、もう一度チェックするかを聞く。
- メモを残すときは `--note "AI で要約して確認"` のように付けられる。
- 要注意は確認済みにしても消えない。ルールに合うよう元の資料が直されたときに消える（それが本人の知りたいことなので）。

## 4. 警告のルールを一緒に作る

「承認が空なら教えて」「金曜までに更新されてなかったら警告して」のように頼まれたら、相談相手として、データを見たうえで具体的な案を出す。本人はルールの書き方を知らなくてよい。決めるのは本人で、あなたは選びやすくする。

**まず、データを見る。** 推測で案を作らず、いまの値を確かめてから話す。

```
watchpoint fields <name>      # 列ごとに: 何行中何行が空か、どの行が空か、どんな値がいくつあるか
watchpoint rule list <name>   # いまのルールと期限、いまの要注意
```

**次に、根拠付きの案を 2〜4 個出す。** 何を見てそう考えたかを添えると、本人が判断しやすい。

- 空の欄: 「回答 の列は 5 行中 2 行が空です（No.3・No.4）。どちらも 状態 が未回答なので、『回答済の行は 回答 を空にしない』にすると、回答漏れだけを拾えます」
- 決まった値: 「状態 の値は 未回答・回答済 の 2 種類だけです。『この 2 つのどれか』にすると、打ち間違いや想定外の値（保留 など）に気づけます」
- 期限: 「毎週の定例の資料なら『毎週金 17:00 までに更新』のように決めると、更新が漏れた週に分かります。ふだん何曜の何時ごろ更新されますか？」
- 本人が言っていないが役に立ちそうなものは、押し付けずに一つだけ「こういうのもできます」と添える。

**分からないことは聞く。ただし少なく、答えやすく。** 一度に 1〜3 個、選択肢を付けて聞く（「全部の行ですか、回答済の行だけですか？」）。警告の文言を本人の言葉にしたいかも聞くとよい（「承認漏れ」のように短く）。

**足す前に、いま何が引っかかるかを見せる。**

```
watchpoint rule add <name> --field 回答 --required --when 状態=回答済 --dry-run
```

「このルールだと、いま 1 件（No.2）が引っかかります」と伝え、それで良いかを聞く。思ったより多い・少ないときは、条件を一緒に直す。

**本人が「それで」「お願い」と言ったら足す。** 言われるまでは足さない（ルールは本人の通知を増やすものなので）。

```
watchpoint rule add <name> --field 回答 --required --when 状態=回答済 -m "回答漏れ"
watchpoint rule add <name> --field 状態 --one-of 未回答,回答済
watchpoint expect <name> "毎週金 17:00"        # 平日 9:00 / 毎日 9:00 / 毎月25日 17:00 / 3d も書ける
watchpoint rule remove <name> <番号>           # rule list の番号
watchpoint expect <name> --clear
```

- 足したら、何を足したかを一言で伝える（次のチェックから「要注意」として出る、画面の「ルールと期限」でも見られる・外せる、と添える）。
- 値のルールが付けられるのは、行ごとに見る見張り（key のある Excel・CSV・JSON）と、決まったセルの見張りだけ。それ以外で頼まれたら、期限（`expect`）なら付けられること、見張り方を変えるなら本人が画面で行うことを伝える。
- 「大事そうな変更なら教えて」のように、決まった規則にできない判断は、ルールではなく「知らせる条件」（AI が読む指示）に向いている。それは画面の見張りの設定で本人が書くものなので、書くとよい文の案を示す。

## やらないこと

本人の環境や判断に関わることなので、頼まれてもコマンドを示して本人に動かしてもらう。

- 設定ファイル（targets.yaml）を直接書き換えない。見張りの追加や変更は、本人が `watchpoint gui` の画面で行う。ルールと期限だけは、本人が合意したあと、上の `rule` / `expect` コマンドで足してよい（このコマンドは設定の誤りを確かめ、前の内容を .bak に残し、ほかの行には触れない）。
- `watchpoint allow`（コマンドを動かす許可）を動かさない。とくに `--unsafe` は、本人が警告を読んで判断するためのもの。
- `watchpoint schedule install` / `uninstall`、`watchpoint clean --yes`、`watchpoint secret set` / `delete` を動かさない。
- 見張っている元のファイルを開いたり書き換えたりしない。中身を見たいときは `watchpoint open <name>`（読み取り専用のコピーを開く）、場所を見たいときは `watchpoint open <name> --place`。
